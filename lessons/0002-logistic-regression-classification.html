Logistic Regression & Classification

Lesson 2 · Milestone 2 · Load-bearing derivation #2 · Reading ahead

Linear regression predicts a number. But what if the answer is yes or no? Spam or not spam? Malignant or benign? You need a model that outputs a probability — a number between 0 and 1 — and a loss function designed for that.

Logistic regression is that model. It's linear regression with one crucial addition: a function that squashes the output into [0, 1]. That function is the sigmoid, and understanding it — and the loss function it demands — is your second load-bearing derivation.

From Lines to Probabilities

In linear regression, the model outputs:

z = w · x + b

This can be any real number: −∞ to +∞. That's fine for predicting house prices, but useless for "probability of spam." We need to squash z into [0, 1].

The Sigmoid Function

σ(z) = 1 / (1 + e⁻ᶻ)

The sigmoid. Large positive z → 1, large negative z → 0, z = 0 → 0.5.

Key properties to internalise:

  • Range is (0, 1) — it's always a valid probability.
  • σ(0) = 0.5 — the decision boundary. When the linear part (w·x + b) is exactly 0, the model is maximally uncertain.
  • Symmetric: σ(−z) = 1 − σ(z).
  • Beautiful derivative: σ′(z) = σ(z) · (1 − σ(z)). You'll derive this below. It means the gradient is largest at z = 0 (where the model is most uncertain) and vanishes at the extremes (where it's already confident). This will matter a lot in neural nets.

So the full model is:

ŷ = σ(w · x + b) = σ(z)

We interpret ŷ as P(class = 1 | x). If ŷ > 0.5, predict class 1; otherwise class 0.

For an interactive visualisation of sigmoid, see 3Blue1Brown's neural networks series, which uses sigmoid in the activation function context. MML Book §12.2.2 covers the sigmoid in detail.

Why Not MSE?

You might think: just use MSE like before. Predictions are numbers, targets are 0 or 1, minimise the squared difference. This is a trap.

MSE for Classification

When the model outputs 0.99 for a true positive, the MSE gradient is tiny: 2·(0.99 − 1)·σ′(z) ≈ 0. The model is right and barely updates — fine.

But when the model outputs 0.01 for a true positive (badly wrong), the MSE gradient is also tiny: 2·(0.01 − 1)·σ′(z) where σ′(z) ≈ 0 because z is very negative. The model is wrong and still barely updates.

The Problem

MSE + sigmoid creates a non-convex loss surface with flat regions where the gradient nearly vanishes — even though the model is making confident, wrong predictions.

Gradient descent gets stuck in these flat regions. You need a loss function that screams louder the more confidently wrong you are.

Cross-Entropy Loss

The right loss function for classification is binary cross-entropy (also called log loss):

L = −(1/n) Σ [ y_i · log(ŷ_i) + (1 − y_i) · log(1 − ŷ_i) ]

Parse it piece by piece:

  • When yi = 1 (positive class): only the log(ŷ_i) term survives. If ŷ ≈ 1, log(1) = 0 → no penalty. If ŷ ≈ 0, log(0) → −∞ → infinite penalty.
  • When yi = 0 (negative class): only the log(1 − ŷ_i) term survives. If ŷ ≈ 0, log(1) = 0 → no penalty. If ŷ ≈ 1, log(0) → −∞ → infinite penalty.
  • The negative sign flips it so we're minimising (logs of probabilities are negative).
Cross-entropy penalises confident wrong answers exponentially more than tentative ones. A prediction of 0.51 for a true 1 costs almost nothing. A prediction of 0.01 for a true 1 costs enormously. This is exactly the property MSE was missing.

The information-theoretic derivation of cross-entropy (why logs, specifically) is in MML Book §6.6. For the practical ML perspective, see CS229 Lecture 3.

Load-Bearing Derivation #2

Two things to derive: the sigmoid's derivative (needed for the chain rule), and the gradient of cross-entropy loss with respect to the weights.

Part A: Derivative of the Sigmoid

Start from σ(z) = 1/(1 + e⁻ᶻ) = (1 + e⁻ᶻ)⁻¹. Apply the chain rule:

σ'(z) = −(1 + e⁻ᶻ)⁻² · (−e⁻ᶻ)
      = e⁻ᶻ / (1 + e⁻ᶻ)²

Now the trick: rewrite e⁻ᶻ/(1 + e⁻ᶻ)² by noting that:

σ(z) = 1/(1 + e⁻ᶻ)
1 − σ(z) = e⁻ᶻ/(1 + e⁻ᶻ)

So:

σ'(z) = σ(z) · (1 − σ(z))

Elegant. The derivative of the sigmoid is expressed entirely in terms of itself. This makes backpropagation cheap: if you've already computed σ(z) during the forward pass, you get the derivative for free.

Part B: Gradient of Cross-Entropy w.r.t. w

For one sample, the loss is:

ℓ = −[ y·log(σ(z)) + (1−y)·log(1 − σ(z)) ]

where z = w·x + b. We want ∂ℓ/∂w. Chain rule: ∂ℓ/∂w = ∂ℓ/∂σ · ∂σ/∂z · ∂z/∂w.

∂ℓ/∂σ (how loss changes with the prediction):

∂ℓ/∂σ = −[ y/σ − (1−y)/(1−σ) ]
       = −[ y/σ − (1−y)/(1−σ) ]

∂σ/∂z (sigmoid derivative, from Part A):

∂σ/∂z = σ(1 − σ)

∂z/∂w (same as linear regression):

∂z/∂w = x

Multiply them together:

∂ℓ/∂w = −[ y/σ − (1−y)/(1−σ) ] · σ(1−σ) · x

Now watch the cancellation. Expand the bracket:

= −[ y(1−σ) − (1−y)σ ] · x
= −[ y − yσ − σ + yσ ] · x
= −[ y − σ ] · x
= (σ − y) · x
= (ŷ − y) · x

Over all samples:

∂L/∂w = (1/n) Σ (ŷ_i − y_i) · x_i
Look at that result. The gradient of cross-entropy loss for logistic regression is (1/n) Σ (ŷ − y) · x — almost identical to linear regression's gradient (minus the factor of 2). The sigmoid and the log-loss were designed to cancel each other's complexity. This is not a coincidence; it's a consequence of choosing the "natural" loss function for the sigmoid (its canonical link function, in statistics language). The update rule is the same shape: w ← w − lr · (1/n) · Xᵀ · (ŷ − y).

The Decision Boundary

The model predicts class 1 when ŷ > 0.5, i.e. when σ(z) > 0.5, i.e. when z > 0:

w · x + b > 0     →    predict class 1
w · x + b < 0     →    predict class 0
w · x + b = 0     →    the decision boundary

In 2D (two features), w₁x₁ + w₂x₂ + b = 0 is a line. In 3D, a plane. In general, a hyperplane. The weight vector w is perpendicular to this boundary — it points toward the "class 1" side. The bias b shifts the boundary away from the origin.

Training logistic regression is finding the hyperplane that best separates the two classes. Gradient descent nudges the plane's orientation (w) and position (b) until the cross-entropy loss is minimised. The decision boundary is where the model is exactly 50/50 uncertain.

Evaluation: Beyond Accuracy

This is where precision and recall enter — concepts woven through Milestones 1–3.

Precision

"Of everything I called positive, how many actually were?"

TP / (TP + FP)

High precision = few false alarms.

Recall

"Of everything that was actually positive, how many did I catch?"

TP / (TP + FN)

High recall = few missed cases.

There's usually a tension: raising the classification threshold (say from 0.5 to 0.8) increases precision but decreases recall. Which matters more depends on the problem — spam filters optimise for precision (don't delete real email), medical screening optimises for recall (don't miss a cancer).

Also introduced here: train/test split. If you evaluate on the same data you trained on, you're measuring memorisation, not generalisation. Split your data, train on one part, evaluate on the other. We'll build this into the code scaffold for Milestone 2.
