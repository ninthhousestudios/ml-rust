Linear Regression & Gradient Descent

Lesson 1 · Milestone 1 · Load-bearing derivation #1

You have a bunch of data points. You suspect there's a line hiding in them. Linear regression finds that line — but the interesting part isn't that it finds the line, it's how: by defining "wrong" as a number, then walking downhill on the wrongness surface until you reach the bottom.

That walking-downhill process is gradient descent, and it's the engine underneath nearly everything else in this curriculum — neural nets, transformers, all of it. This is where you learn to trust it.

The Setup

Given n data points (xi, yi), we want to find weight w and bias b such that:

ŷ_i = w · x_i + b

predicts yi as closely as possible. With multiple features (a vector xi of dimension d), this generalises to:

ŷ = X · w + b

where X is (n × d), w is (d × 1), and b is broadcast to every row. This is why you built Matrix first — the prediction step is a single matmul.

Measuring Wrongness: MSE

We need a single number that says "how wrong are all our predictions collectively." Mean Squared Error does this:

MSE = (1/n) Σ (ŷ_i − y_i)²

Why squared? Two reasons that matter:

  1. Positive errors and negative errors don't cancel out. If you overshoot by 5 and undershoot by 5, absolute error says 0 average. Squaring keeps both.
  2. It's smooth and differentiable everywhere, which means we can take its derivative — and that derivative is what gradient descent needs.

For more on loss function choices, see CS229 Lecture 2 (Andrew Ng) or MML Book §8.1.

The Core Idea: Walking Downhill

Think of MSE as a surface. Each possible value of (w, b) is a point on this surface, and the height at that point is the loss. We want to find the bottom — the (w, b) with the lowest loss.

Gradient descent is simple: wherever you're standing, figure out which direction is downhill, take a step that way, repeat.

The gradient ∇MSE tells you the direction of steepest ascent. So you walk the opposite direction: w ← w − lr · ∂MSE/∂w. The learning rate lr controls your step size.

The only question is: what is the gradient? That's the derivation.

Load-Bearing Derivation #1

This is the one you need to own with pen and paper. The result isn't hard, but doing it yourself is what makes gradient descent feel mechanical rather than magical.

Step 1: Write MSE as a function of w

Start with one feature (1D). Predictions are ŷi = w·xi + b. Substituting into MSE:

MSE(w, b) = (1/n) Σ (w·x_i + b − y_i)²

Let's call the error ei = ŷi − yi = w·xi + b − yi.

Step 2: Differentiate with respect to w

Apply the chain rule to each term in the sum. The outer function is (·)², the inner function is ei = w·xi + b − yi:

∂MSE/∂w = (1/n) Σ  2 · e_i · ∂e_i/∂w
         = (1/n) Σ  2 · e_i · x_i          ← because ∂(w·x_i + b − y_i)/∂w = x_i
         = (2/n) Σ  (ŷ_i − y_i) · x_i

The xi factor is the key insight: the gradient of the loss with respect to a weight is scaled by the input. Features with larger values contribute more to the gradient. This will come back in neural nets.

Step 3: Differentiate with respect to b

Same chain rule, but ∂ei/∂b = 1 (bias doesn't scale with input):

∂MSE/∂b = (2/n) Σ (ŷ_i − y_i)

Just the average error, scaled by 2. Simpler because the bias shifts everything uniformly.

Step 4: The update rule

w ← w − lr · ∂MSE/∂w
b ← b − lr · ∂MSE/∂b

Subtract because we want to go downhill (opposite the gradient). lr (learning rate) controls step size — too big and you overshoot, too small and you crawl.

Matrix Form

With d features, you have d weights. The per-feature gradient derivation is the same, but we can express the whole thing as one matrix operation:

predictions = X · w + b           (n × 1)
errors      = predictions − y     (n × 1)
∂MSE/∂w     = (2/n) · Xᵀ · errors (d × 1)
∂MSE/∂b     = (2/n) · sum(errors)  (scalar)

That Xᵀ · errors is doing all the per-feature gradient accumulation in one matmul. Each row of Xᵀ is one feature across all samples; dotting it with the errors vector gives you that feature's total gradient contribution. This is why the Matrix type and transpose() were Milestone 0.

Ng derives this matrix form in CS229 Lecture 2. For the geometric view of gradient descent, see 3Blue1Brown's gradient descent video.

A Note on the 2

The factor of 2 in (2/n) comes from the power rule on (·)². Many implementations drop it — they define MSE as (1/2n) Σ (...)² instead, so the 2 cancels. It doesn't matter: the learning rate absorbs the constant. Keep it or drop it, as long as you're consistent. The scaffold code keeps it.
