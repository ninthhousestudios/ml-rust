Decision Trees & the ML Landscape

Lesson 3 · Milestone 3 · Phase 1 completion · No load-bearing derivation (recognize level)

You've now built two models — linear regression and logistic regression — both powered by the same engine: gradient descent. Compute a differentiable loss, take its gradient, nudge the weights downhill. It's elegant, and it works.

But it has assumptions. Gradient descent needs a differentiable loss function, continuous parameters, and a model whose decision boundary is a hyperplane (or at least something you can parameterize smoothly). What happens when those assumptions don't hold?

This milestone's gate question: when should you NOT reach for gradient descent? By the end, you should have a mental decision tree (pun intended) for picking the right tool.

Entropy: Measuring Disorder

Before we can build a decision tree, we need a way to measure how "mixed up" a set of labels is. That measure is entropy, borrowed from information theory.

H(S) = −Σ p_i · log&sub2;(p_i)

where pi is the proportion of class i in the set S.

What entropy means

  • H = 0 — the set is pure. All labels are the same class. No uncertainty: you already know the answer.
  • H = 1.0 — maximum uncertainty for binary classification (50/50 split). You have no idea which class a random element belongs to.
  • 0 < H < 1 — somewhere in between. The more skewed the distribution, the lower the entropy.

Convention: 0 · log2(0) = 0. A class with zero probability contributes nothing to entropy. (The limit of p·log(p) as p→0 is 0.)

Worked example

Consider a dataset of 6 temperature readings and whether they're "comfortable":

tempcomfortable?
100
150

The full set has 3 zeros and 3 ones. The proportions are p0 = 3/6 = 0.5 and p1 = 3/6 = 0.5.

H(parent) = −(0.5 · log&sub2;(0.5) + 0.5 · log&sub2;(0.5))
           = −(0.5 · (−1) + 0.5 · (−1))
           = 1.0

Maximum entropy — the labels are perfectly mixed.

Now consider just the labels [0, 0, 0, 1] (75% zeros, 25% ones):

H = −(0.75 · log&sub2;(0.75) + 0.25 · log&sub2;(0.25))
  = −(0.75 · (−0.415) + 0.25 · (−2.0))
  = −(−0.311 + (−0.5))
  = 0.811

Lower than 1.0 — the set is skewed toward class 0, so there's less uncertainty.

Entropy answers: "how many yes/no questions would I need to ask, on average, to determine a random element's class?" A pure set needs 0 questions. A 50/50 set needs exactly 1.

Information Gain: How Trees Decide

A decision tree splits data to reduce entropy. The metric for how good a split is is called information gain (IG):

IG = H(parent) − (|left|/|total|) · H(left) − (|right|/|total|) · H(right)

It measures how much entropy decreases after splitting. Higher IG = better split. The tree algorithm tries every possible split and picks the one with highest IG.

Worked example: choosing a split

Using our temperature data, let's compare two candidate thresholds:

Split A: temp ≤ 17.5

Left (temp ≤ 17.5): rows with temp 10, 15 → labels [0, 0] → H = 0 (pure!)

Right (temp > 17.5): rows with temp 20, 25, 30, 35 → labels [1, 1, 1, 0]

H(right) = −(0.75 · log&sub2;(0.75) + 0.25 · log&sub2;(0.25)) = 0.811
IG = 1.0 − (2/6) · 0 − (4/6) · 0.811
   = 1.0 − 0 − 0.541
   = 0.459

Split B: temp ≤ 22.5

Left: temp 10, 15, 20 → labels [0, 0, 1] → H = 0.918

Right: temp 25, 30, 35 → labels [1, 1, 0] → H = 0.918

IG = 1.0 − (3/6) · 0.918 − (3/6) · 0.918
   = 1.0 − 0.918
   = 0.082

Split A wins (IG = 0.459 vs 0.082). It cleanly separates the cold temperatures (pure class 0) from the rest. The tree picks this split first.

Now the right subtree [1, 1, 1, 0] still has entropy 0.811. We recurse and split again at temp ≤ 32.5:

  • Left: [1, 1, 1] → H = 0 (pure)
  • Right: [0] → H = 0 (pure)
  • IG = 0.811 (all entropy eliminated)

The final tree, depth 2:

temp ≤ 17.5? / \ class = 0 temp ≤ 32.5? / \ class = 1 class = 0

This tree captures a non-monotonic relationship: comfortable temperatures are in the middle range [20, 30]. Logistic regression could never learn this — it can only draw a single boundary, meaning "everything above threshold X is class 1." The real boundary here requires two cuts.

This is the central insight of this milestone. Gradient descent finds a hyperplane (one linear boundary). Decision trees carve out arbitrary rectangular regions via recursive splits. When the real decision surface is non-linear, non-monotonic, or axis-aligned, a decision tree wins.

The CART Algorithm

CART (Classification and Regression Trees) is the algorithm you'll implement. Here's the procedure in pseudocode:

function build_tree(data, labels, depth, max_depth):
    if all labels are the same class:
        return Leaf(that class)
    if depth >= max_depth:
        return Leaf(majority class)

    best_ig = 0
    best_feature = None
    best_threshold = None

    for each feature f:
        values = sorted unique values of f in current data
        for each pair of adjacent values (v1, v2):
            threshold = (v1 + v2) / 2
            left_labels  = labels where data[f] <= threshold
            right_labels = labels where data[f] >  threshold

            ig = information_gain(labels, left_labels, right_labels)
            if ig > best_ig:
                best_ig, best_feature, best_threshold = ig, f, threshold

    if best_ig == 0:
        return Leaf(majority class)

    split data into left_data and right_data using best split
    left_child  = build_tree(left_data, left_labels, depth + 1, max_depth)
    right_child = build_tree(right_data, right_labels, depth + 1, max_depth)
    return Split(best_feature, best_threshold, left_child, right_child)

Key implementation details

  • Candidate thresholds: midpoints between sorted unique values. For values [0, 1, 4, 5], the candidates are 0.5, 2.5, 4.5.
  • Row indices: rather than copying matrices, pass around a &[usize] of which rows belong to this node. Use x.get(row, feature) to access values.
  • Majority class: when creating a leaf at max depth, count which class appears more often in the remaining rows.
  • Recursion in Rust: fit() sets up the initial call with all row indices and depth 0. A helper function (free function or method) does the recursion, returning Node and wrapping children in Box::new().

Overfitting and Depth Control

A decision tree with no depth limit will keep splitting until every leaf is pure — even if that means one leaf per training point. This is overfitting: the tree memorises the training data instead of learning general patterns.

Underfitting (too shallow)

max_depth = 1: only one split. Can't capture complex boundaries. Both train and test accuracy are low.

Overfitting (too deep)

No depth limit: one leaf per point. Train accuracy = 100%, but test accuracy drops because the tree learned noise.

max_depth is a hyperparameter — you choose it, not the algorithm. Finding the right value is part of model selection (often via cross-validation, covered below).

The ML Landscape: Beyond Gradient Descent and Trees

Milestone 3 asks you to recognize four more algorithms. You won't implement these, but you should know what they do and when you'd reach for them.

k-Nearest Neighbors (k-NN)

How: to classify a new point, find the k closest training points and take a majority vote. No training at all — all work happens at prediction time.

When: small datasets, similarity-based problems, or as a baseline. Bad for large datasets (must compare against every training point) and high-dimensional data (distances become meaningless — the "curse of dimensionality").

k-Means Clustering

How: partition data into k clusters by iteratively assigning points to their nearest centroid, then recomputing centroids. Unsupervised — no labels needed.

When: you have no labels and want to find natural groups. Common for customer segmentation, image compression, or as a preprocessing step. You choose k, which requires judgment (elbow method, silhouette score).

PCA (Principal Component Analysis)

How: find the directions of maximum variance in the data via eigenvalue decomposition. Project the data onto the top-k principal components, discarding the rest. Not a classifier — a dimensionality reduction technique.

When: too many features (reduce before feeding to another model), or for visualisation (project 100D data to 2D for plotting). Linear only — misses non-linear structure. Often a preprocessing step, not a model itself.

SVM (Support Vector Machine)

How: find the hyperplane that separates classes with the maximum margin (largest gap between the boundary and the nearest points on each side). The "support vectors" are the critical points touching the margin. The kernel trick allows SVMs to find non-linear boundaries by implicitly mapping to higher-dimensional space.

When: binary classification with a clear margin, small-to-medium datasets, especially in high dimensions. SVMs were the go-to before deep learning; they're still strong for specific problems. Less interpretable than trees, more so than neural nets.

CS229 covers all four: k-NN informally in early lectures, k-means in Lecture 12, PCA in Lecture 14, SVMs in Lectures 6–7. The MML Book covers PCA rigorously in §10 and SVMs in §12.2.

Model Evaluation Toolkit

This section completes the evaluation thread woven through Milestones 1–3. You implemented accuracy in logreg; now add the tools to know whether that accuracy number actually means anything.

The Confusion Matrix

Actual Positive (1)Actual Negative (0)
Predicted Positive (1)TP (true positive)FP (false positive)
Predicted Negative (0)FN (false negative)TN (true negative)

Everything else derives from these four counts:

  • Accuracy = (TP + TN) / total
  • Precision = TP / (TP + FP) — "of my positive predictions, how many were right?"
  • Recall = TP / (TP + FN) — "of the actual positives, how many did I find?"

Train/Test Split

If you evaluate on the data you trained on, you're measuring memorisation, not generalisation. Always split your data: train on one portion, evaluate on the held-out portion. Typical splits: 80/20 or 70/30.

A model that achieves 100% train accuracy and 55% test accuracy has overfitted. The gap between train and test performance is the clearest signal of overfitting. Reducing model complexity (e.g., shallower tree) narrows the gap.

Cross-Validation

A single train/test split can be noisy — the result depends on which rows ended up in which set. k-fold cross-validation is more robust:

  1. Split data into k equal folds (typically k = 5 or 10).
  2. For each fold: train on the other k−1 folds, evaluate on this fold.
  3. Average the k scores.

Every data point gets evaluated exactly once. The average is a more stable estimate of model performance than any single split. You won't implement this now, but know it exists — it's the standard way to compare models or tune hyperparameters like max_depth.

When NOT to Use Gradient Descent

This is the gate. After building linreg, logreg, and now a decision tree, you should be able to look at a problem and pick the right family of tools:

SituationReach for…Why
Continuous features, linear relationship, predicting a number Linear regression (GD) Simple, fast, interpretable; GD finds the optimal weights
Continuous features, binary classification, linear boundary Logistic regression (GD) Same engine as linreg with sigmoid; finds the best hyperplane
Non-linear boundary, mixed/categorical features, need interpretability Decision tree No differentiability needed; handles XOR-type patterns; human-readable
Small dataset, similarity matters, quick baseline k-NN No training, instant setup; limited by dataset size at prediction time
No labels, looking for structure k-means / PCA Unsupervised; finds groups (k-means) or reduces dimensions (PCA)
Binary classification, clear margin, many features SVM Maximum margin; kernel trick handles non-linear; strong in high dimensions
Lots of data, complex patterns, willing to lose interpretability Neural network (Milestone 4+) GD on steroids: learns its own features via backprop. You'll build this next.
Gradient descent assumes a differentiable loss over continuous parameters. Decision trees assume nothing about the loss shape — they work by exhaustive search over splits. That's why they complement each other: gradient descent is efficient when its assumptions hold; decision trees are robust when they don't.
