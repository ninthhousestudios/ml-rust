# Mission: Machine Learning

## Why

I enjoy learning, I'm working heavily with AI and Rust right now, and ML is the intersection
that feels most exciting and interesting to me. I want to understand the machine — not as a
consumer of APIs, but as someone who has built the core pieces and knows why they work.

## Success looks like

- I can explain how a transformer works without hand-waving — Q/K/V, attention, the lot
- I can build and train a small neural network from scratch in Rust, understanding every line
- I can read the ML code in my own stack (smriti, chitta) and know what it does and why
- I can run Flux inference from a single Rust binary for the nhs/lora project
- The gap between "I use Claude" and "I understand roughly how Claude works" is closed

## Constraints

- Self-paced, on/off cadence — no calendar pressure
- Rust, not Python — the language is part of the learning, not an obstacle to route around
- Math BS (rusty but fundamentals are there) — explanations can assume mathematical maturity
- Learning Rust concurrently — don't assume Rust fluency
- Hand-roll core concepts first; only use crate frameworks (candle, burn, ndarray) after the
  fundamentals are owned

## Out of scope

- Employment-oriented ML (interview prep, Kaggle competition optimization)
- Deep dives into proofs beyond the four load-bearing derivations
- Python/PyTorch (except as conceptual reference — "this is what micrograd does in Python")
- Production ML engineering (MLOps, model serving, data pipelines)
